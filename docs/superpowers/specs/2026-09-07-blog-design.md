# AstroPaper 기술 블로그 설계

사용자가 승인한 범위: AstroPaper, 옵시디언의 표준 Markdown 작성, GitHub 푸시 후 GitHub Pages 자동 배포, 시리즈 연재.

## 구조

- 공식 AstroPaper 소스를 사용하고 MIT 라이선스를 유지한다.
- `src/content`를 옵시디언 보관함으로 사용한다. `posts/`는 글, `series/`는 시리즈 소개, `pages/`는 소개 페이지, `_templates/`는 작성 템플릿이다. 시리즈 소개도 옵시디언에서 편집해야 하므로 처음 제안한 posts보다 한 단계 상위 폴더를 연다.
- 본문은 `.md`만 지원한다. 위키링크, 옵시디언 임베드, 전용 콜아웃을 사용하지 않는다. YAML frontmatter는 Astro 콘텐츠 메타데이터로 유지한다.
- 상대 `.md` 링크는 실제 발행 URL로 변환한다. 존재하지 않는 글이나 공개 글에서 초안으로 향하는 링크는 빌드를 실패시킨다. 이미지 상대 경로는 Astro의 이미지 처리를 사용한다.
- 블로그 기본 언어는 한국어, 시간대는 Asia/Seoul이다. 기본 검색, RSS, 사이트맵, 다크 모드와 코드 강조를 유지한다.

## 시리즈

- 글에 선택 필드 `series`(영문 소문자/숫자/하이픈 식별자)와 `seriesOrder`(양의 정수)를 함께 지정한다.
- 시리즈 소개는 `series/<id>.md`의 title, description과 본문으로 작성한다.
- `/series/`는 공개 회차가 있는 시리즈만, `/series/<id>/`는 공개 회차를 숫자순으로 표시한다.
- 글의 시리즈 목차는 현재 회차를 표시하며 이전/다음 공개 회차로 연결한다. 일반 글에는 기존 시간순 탐색을 유지한다.
- 미정의 시리즈, 중복 회차, 한쪽 필드만 있는 글, 유효하지 않은 회차는 빌드를 실패시킨다. 초안과 미래 글은 공개 페이지, RSS, 검색, 시리즈 탐색에서 제외한다. 예약 시각 도달만으로 배포되지 않으며 다음 빌드 때 반영된다.

## 배포와 검증

- Node 24, npm lockfile과 `npm ci`로 설치를 재현한다.
- main 푸시와 수동 실행으로 검사, 테스트, 빌드, Pages 배포를 실행한다. PR에서는 검증만 수행한다.
- GitHub Pages 메타데이터로 site/base를 전달해 사용자 사이트와 저장소 하위 경로를 지원한다.
- 시리즈 정렬/노출/검증과 Markdown 링크 변환을 자동 테스트한다. 프로덕션 빌드 결과에서 시리즈 탐색, 이미지, 초안 제외와 하위 경로 링크를 검증한다.
- 현재 환경의 `.git`은 비어 있는 읽기 전용 디렉터리다. 커밋/푸시와 원격 Pages 활성화는 할 수 없으므로 구현물을 남기고 README에 사용자 절차를 기록한다.
